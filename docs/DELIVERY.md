# Forma Demo 交付说明

Forma 是一个通过对话生成和迭代网页应用的可运行原型。用户描述需求后，可查看 Agent 公开进展及文件变更，在右侧操作作品，编辑源码并保存版本；修改不满意时可以恢复历史版本继续迭代。

状态日期：2026 年 10 月 21 日。当前范围是前端应用生成，不包含为生成作品自动配置业务后端。

## 访问与体验

- [在线演示](https://forma.coder-cengdong.site)：访客可直接体验四个交互示例；创建自己的项目需 Google 登录。
- [GitHub 源码](https://github.com/testerxiaodong/atoms-like-demo)：包含启动配置、数据库迁移及测试。
- [测试记录](TESTING.md)与 [GitHub Actions](https://github.com/testerxiaodong/atoms-like-demo/actions)。

建议体验路径：登录后输入“做一个带筛选和完成状态的待办清单” → 查看文件生成进度 → 在右侧新增并完成待办 → 继续要求调整功能 → 打开代码编辑并保存 → 恢复历史版本 → 刷新确认项目与版本保留。也可在生成期间停止，再重新发送；项目列表右上角菜单支持确认删除。

**演示运行条件：** 页面与业务后端部署在 Vercel 孟买，与 Supabase 数据库同区域。本机只运行 Codex Worker，主动领取后台任务；浏览、编辑与预览无需本机在线，生成仍需本机 Worker 在线。演示同时只处理一个模型任务，生成最长 600 秒；页面刷新不取消任务，但本机进程崩溃后的计算不能续算。

## 实现思路与关键取舍

系统围绕一条闭环实现：需求输入 → 鉴权与项目读取 → Agent 生成候选文件 → 源码检查与编译 → 数据库事务保存 → 页面预览。模型输出只有通过检查后才成为项目的新版本，停止或失败不覆盖已有代码。

| 选择                                       | 原因与边界                                                                                                                                                                                  |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Next.js App Router、TypeScript             | 页面和接口放在同一仓库，减少第一版的服务拆分和部署复杂度。                                                                                                                                  |
| Tailwind、shadcn/ui、Base UI、Lucide       | 复用开源界面基础；项目菜单、确认弹窗、Agent 文件进度、编辑预览分别封装。Button/Tooltip 复用 Base UI；Card/Badge/Textarea/Alert 统一样式；示例展示用局部 CSS，移动端布局与键盘交互纳入回归。 |
| 单 Agent 与两种模型适配                    | API 模式用 AI SDK 工具循环读取、修改和校验文件；当前演示用 Codex CLI 逐个返回候选源码，最后提交文件清单。两条路径共用检查与保存流程，暂不引入多 Agent 调度。                                |
| Supabase Auth 与 PostgreSQL                | 复用 Google 登录和托管数据库；RLS 隔离用户读取，事务函数校验所有者、版本号和运行锁。普通业务使用用户 JWT；管理密钥只用于云端受 Worker 密钥保护的任务接口，不传给浏览器或本机。              |
| CodeMirror 编辑、esbuild 编译、iframe 预览 | 复用编辑器和编译工具，在服务端打包而不执行生成应用；作品在受限 iframe 中运行。运行依赖由平台限定，暂不支持任意 npm 包和生成作品联网请求。                                                   |
| 云端持久化任务 + 本机 Worker               | 云端与数据库同区部署降低业务接口延迟；生成通过短请求入队和进度轮询，避开函数长连接时限。保留单执行名额、超时和原子提交，暂不支持 Worker 崩溃后续算。                                        |

平台、源码、消息、运行记录及版本保存在云端。生成作品自身的待办、游戏分数等业务状态取决于作品实现，不等同于平台已提供业务数据库。

## 已完成与未完成

**已完成：** Google 首次登录建号和换号入口；独立登录/注册页面；登录前草稿保留与登录后自动继续；四个匿名交互示例；项目列表和删除；生成与继续修改；逐文件候选进度；代码编辑与保存；右侧交互预览、手机宽度、刷新与错误提示；消息及源码持久化；失败/停止后重试；版本历史与恢复；接口校验、账号隔离、版本竞争及测试流水线。

**延展能力是可回溯的版本迭代。** AI 生成与手动保存都会产生快照；恢复历史内容会创建一个新版本，保留原历史，下一轮生成从恢复后的源码继续。它既支持尝试不同方案，也为失败恢复和工程追踪提供基础。文件进度展示和原子提交让用户能够区分“正在生成的候选结果”和“已保存的作品”。

交付要求对应：

| 要求                   | 当前实现与验收入口                                                                |
| ---------------------- | --------------------------------------------------------------------------------- |
| 可运行且有真实交互     | 登录后描述需求并生成 React 应用，右侧 iframe 可直接操作；四个匿名示例用于快速体验 |
| 数据持久化             | 项目、消息、源码、运行记录和版本保存至 Supabase，刷新后可恢复                     |
| 初始化与核心流程       | 独立登录/注册页、Google 首次授权建号、创建、生成、编辑、保存、预览、删除          |
| 至少一个延展能力       | 版本历史与恢复，恢复形成新快照，不覆盖历史                                        |
| 在线访问与源码         | 本文顶部的固定域名和公开 GitHub 链接                                              |
| 思路、完成度与后续计划 | 本文选型表、已完成/未完成清单及后续优先级；验证证据见测试文档                     |

**未完成：** GitHub 登录、作品一键导出/独立发布、与 GitHub 双向同步、生成作品的后端与数据库、多用户实时协作、完整版本差异比较、自动浏览器测试与修复循环、Worker 崩溃后的任务续算与自动调度、完善的用户额度与运维监控。当前整体定位为可体验 MVP。

## 工程质量与验证证据

2026-10-21 当前版本本地完整回归：规范、类型、单元/集成、浏览器/HTTP 和生产构建均通过。默认 Vitest **88 passed / 2 skipped**，Playwright **59 passed / 3 skipped**；默认跳过项依赖真实服务，运行条件与补跑记录见测试文档。最新提交的流水线状态见 [GitHub Actions](https://github.com/testerxiaodong/atoms-like-demo/actions)。

另外已执行真实 Codex 逐文件协议检查，验证至少四个候选文件消息及最终应用编译；固定域名长生成曾实测约 146 秒完成、收到 13 次保活，并验证右侧作品交互与刷新恢复。这些是具体回归结果，不代表每次模型生成都会成功。

真实云端删除相关两轮各有五项功能检查通过，但原有数据在测试窗口内变化，使整窗完整性断言失败；相关临时账号及测试记录已另行确认零残留，不能将这两轮写作整体通过。Google 第三方同意页仍需发布前用目标账号手动验收。共享云端回归应安排无写入窗口或改用独立测试项目。

当前验收：同区云端队列已通过固定域名真实 Codex 停止、重发、刷新恢复与右侧交互预览回归；该轮 **3 项通过**，2 个测试账号和 5 个测试项目已清理，原有五张业务表数据未变。详见 [最新测试记录](TESTING.md#当前验收摘要)。

已知体验限制：迁移前公网创建接口曾需 **3.44–5.27 秒**；迁移到同区域后，固定域名版本列表实测 **589–865 毫秒**（路由约 38–52 毫秒），创建项目 **619–1418 毫秒**。公网会波动，模型任务仍可能持续数分钟。候选文件完成后逐个显示，不提供文件内容的逐字流。源码检查与打包不等于完整类型检查或生成作品的业务验收。

## 后续投入优先级

1. **P0 交付稳定性与响应速度。** 同区域部署与持久化任务已落地；下一步替换为适合在线服务的模型接入，增加 Worker 崩溃恢复、状态监控、用户配额与独立测试环境。先解决可用性与等待时间，再扩大功能范围。
2. **P1 提升生成成功率。** 接入浏览器运行检查，收集运行错误并触发有次数上限的修复；增加变更差异与版本对比，让用户更容易判断和撤回修改。
3. **P1 完善作品交付。** 导出完整工程与依赖清单，支持独立发布及 GitHub 同步，使原型能够离开编辑器继续使用。
4. **P2 扩展使用场景。** 增加后端模板与业务数据存储，再考虑协作、模板社区和更多登录方式。GitHub 登录能改善入口体验，但优先级低于生成可靠性与产物交付。
