## 运行真实 Codex 测试

前置条件：本机 `codex` 命令可用，已用自己的 ChatGPT 账号登录，网络可访问模型服务。测试直接调用 CLI，不需要启动网页应用；不会在业务数据库创建项目。不要在 CI 或仓库中上传 Codex 登录凭据。

```sh
FORMA_CODEX_SMOKE=1 FORMA_CODEX_PROGRESS_SMOKE=1 \
  npx vitest run tests/integration/local-codex.test.ts
```

该文件还包含 3 项普通断言，因此预期结果是 **5 passed、0 skipped**，其中真实模型检查为 2 项。两项测试的超时分别为 90 秒和 290 秒；超时或网络错误应排查后重跑，不能当作通过。需要指定 CLI 时可显式设置 `CODEX_CLI_PATH`；这个直接运行命令不会自动读取 `.env.local`。

多文件测试验证进度事件和预览构建，不等同于在浏览器中实际操作秒表；右侧预览交互另由浏览器回归与发布验收覆盖。

## 运行 3 项真实云端数据库测试

前置条件：

- `.env.local` 中配置目标 Supabase 的 `NEXT_PUBLIC_SUPABASE_URL` 和 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`，已执行所需数据库迁移。
- 被 Git 忽略的 `.env.cloud-test` 中配置 `CLOUD_TEST_EXPECTED_HOST` 和 `SUPABASE_SERVICE_ROLE_KEY`。需要代理时设置 `CLOUD_TEST_PROXY`。不要把密钥写进命令、测试报告或提交记录。
- localhost:3001 可用。编排脚本会启动独立测试应用，不复用演示服务。
- 测试期间暂停对同一数据库的人工修改；清理阶段会对原有数据做前后哈希核对，其他用户正常写入也会使“原数据未变”检查失败。

只补跑这 3 项：

```sh
npm run test:http:cloud -- --grep 'cloud '
```

当前这 3 项的标题均包含 `cloud `，预期为 **3 passed**。不要直接设置 `CLOUD_TEST_URL` 绕过编排：编排负责创建测试账号、限制目标数据库并清理数据。

发布涉及接口、迁移或权限变更时，建议运行完整云端 HTTP 套件：

```sh
npm run test:http:cloud
```

云端套件使用真实 Auth、PostgREST 和 PostgreSQL；模型采用确定性替身。真实模型由上一节独立验证。

### 清理与失败恢复

编排创建两个专用临时账号，所有测试项目归属于它们。管理密钥仅用于准备和清理，不传给应用或 Playwright。清理严格按本次用户 ID 和运行标记执行，不按名称批量删除。

测试断言通过后，还必须确认命令退出码为 0，且输出 `Cleanup verified`。本地 `cloud-test-results/cloud-<运行ID>.json` 应包含 `status: "passed"` 和已验证清理的 `cleanup` 字段，确认：

- 本次测试账号已不存在；测试项目及其版本、消息、运行记录均无残留。
- `projects`、`versions`、`messages`、`runs` 四张表原有记录哈希与测试前一致。

断电、强制终止或清理失败时，保留该次运行记录并执行：

```sh
npm run test:http:cloud:cleanup -- cloud-test-results/cloud-<运行ID>.json
```

替换为本次实际记录路径。恢复清理成功不代表测试断言通过；仍需检查原测试结果。运行记录包含内部账号和项目 ID，继续留在被 Git 忽略的目录，不上传公开仓库。

## 固定域名、隧道与真实模型的长任务回归

本地 HTTP/E2E 使用模型替身，独立 Codex smoke 不经过浏览器和 Cloudflare；两者通过仍不能证明公网长连接可靠。2026-10-21 的公网 `network error` 暴露了这个覆盖缺口。

发布前启动最终演示环境，再运行：

```sh
npm run demo:start
npm run test:public:long
```

前置配置：`.env.demo` 的 `DEMO_ORIGIN` 为最终 HTTPS 域名，命名隧道在线，本机 Codex 已登录，`.env.cloud-test` 配置与云端 HTTP 测试一致。不要在测试期间另外生成项目或修改云端数据，否则原有数据哈希核验会报错。

`playwright.public.config.ts` 不启动本地替身服务器。浏览器实际经过固定域名和隧道，从首页输入创建项目，调用部署服务中的真实模型，验证：

- 生成完成事件、至少 120 秒的连接和至少 10 次保活，接收数据最大间隔小于 25 秒。
- 贪吃蛇在右侧预览可启动、暂停；版本持久化为 revision 1、运行锁释放，刷新后作品仍在。
- 记录首页加载、代码与预览切换、长任务耗时、最大数据间隔及浏览器长任务指标。切换耗时目前用于观测，不作为不稳定公网环境的硬性性能门禁。

模型如果提前完成，测试会明确报“未覆盖 120 秒”，不能把短任务成功当作长连接成功；重新运行并检查模型是否完成全部要求。测试失败也执行清理，断电后的恢复方式同上。HTML 报告位于 `cloud-test-results/public-report`，运行清理凭证仍为 `cloud-test-results/cloud-<运行ID>.json`，不上传账号信息或报告到公开仓库。

该项单独列为发布前检查，不进入默认 CI：它依赖个人电脑在线、真实订阅、云端凭证并消耗实际模型额度。它使用专用测试账号密码建立会话，不覆盖 Google 授权页面；Google 回调仍按手动清单回归。

预览性能回归 `tests/e2e/recovery.spec.ts` 额外验证：代码/预览切换保留作品交互状态；点击刷新重置作品但不重新请求编译。已有源码编辑用例继续验证修改后会重新编译，防止优化引入旧预览。

### Lighthouse 首屏检查与按需加载

用户提供的报告：FCP/LCP 1.2 秒、TBT 0、CLS 0，文档响应等待约 3.61 秒，提示未使用 JS 约 500 KiB。随后同一时段测量，公网匿名首页/登录页首字节分别约 1.55/1.50 秒，本机登录页约 0.0065 秒，说明公网等待存在波动；这些等待不等同于应用服务器计算耗时。报告中的文本压缩和重定向检查已通过。

首页只在退出时需要 Supabase 浏览器 SDK；登录/注册也只在点击授权时需要。改为事件发生时动态导入，避免首屏加载 SDK。生产构建首页 HTML 声明的现代浏览器 JS（排除 `nomodule` 兼容脚本，不包含后续预取）原始体积从 **753,496 B → 495,136 B**，减少 **258,360 B / 34.3%**；对这些文件逐个 gzip 的估算合计 **218,176 B → 151,167 B**，减少 **67,009 B**。这不是浏览器实际传输字节或 Lighthouse 新分数，需重新审计才能比较完整报告。
